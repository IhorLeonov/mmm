# Бюро хороших дней ✳

Маленькое приложение для Maria: фотографии, выбор настроения, три помощника, убегающий плед, кошачья мини-игра и личный рецепт на вечер. Тон дружеский, без романтических признаний. Написано на React, обычном CSS и Vite. Серверная функция отправляет результат через Resend.

## Запуск

Нужен Node.js 22.12+ (или более новая поддерживаемая версия).

```bash
npm install
npm run dev
```

Адрес появится в терминале. Локально работает и `/api/results`: Vite подключает тот же обработчик, что использует Vercel.

```bash
npm run build
npm test
```

## Что уже внутри

- Два настроения с фотографиями Maria.
- Четыре варианта помощи и две детали для каждого.
- Три помощника: её настоящий серый кот, капибара и голубь.
- 48 сочетаний решений: 8 основных рецептов с разными вступлениями и комментариями помощника.
- Секрет: смешной кот → голубь → кот с приветом.
- Плед убегает от мышки и прикосновений. С клавиатуры у него тоже нет шансов на отпуск.
- Мини-игру можно пропустить. Спокойный путь тоже даёт финал.
- Сохранение прогресса в браузере, тихие звуки по желанию, скачивание рецепта в PNG.
- Результат отправляется только после понятной кнопки в финале. В письмо входят настроение, все решения, прохождение мини-игры и финальный рецепт. Фотографии в письмо не отправляются.

## Персонализация

Имя, финальная записка и пути к фотографиям находятся в `src/config.js`. В `src/story.js` — реплики и варианты решений. Стиль — в `src/styles.css`.

В `public/photos/` уже добавлены три предоставленные фотографии. Кадрирование выполняется CSS: исходники сохранены, дополнительных сервисов обработки нет. Фотография в ванной не используется. Рыжий сгенерированный кот не используется — куратор взят с настоящей фотографии.

## Почта и Vercel

1. Создай аккаунт [Resend](https://resend.com) на **pancishi1@gmail.com** и получи API-ключ в разделе API Keys. Не публикуй ключ в GitHub и не вставляй его в чат.
2. Отправь проект в свой GitHub-репозиторий и импортируй его в Vercel. Framework preset: **Vite**. Сборка: `npm run build`. Output directory: `dist`. Функция `/api/results` подключается автоматически.
3. В **Vercel → Project → Settings → Environment Variables** добавь:

   | Переменная | Значение |
   | --- | --- |
   | `RESEND_API_KEY` | Твой ключ `re_…` |
   | `RESULTS_EMAIL` | `pancishi1@gmail.com` |
   | `EMAIL_FROM` | `Бюро хороших дней <onboarding@resend.dev>` |

4. Выполни Deploy / Redeploy после добавления переменных. Пройди историю и отправь результат кнопкой в финале. Для окончательной проверки проверь входящие, спам и журнал Resend.

Адрес `onboarding@resend.dev` подходит для тестовой отправки **на почту владельца аккаунта Resend**. Поэтому проще зарегистрировать аккаунт именно на указанный Gmail. Для другого получателя понадобится подтверждённый домен и соответствующий `EMAIL_FROM`. [Ограничение описано в документации Resend](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain).

Для проверки отправки на компьютере скопируй `.env.example` в `.env.local`, добавь ключ и перезапусти `npm run dev`. `.env.local` уже исключён из Git. Переменные не имеют префикса `VITE_` и доступны только серверу.

Без настроенной почты всё приключение доступно. При отправке появляется честное сообщение о недоступности почтового голубя; успешная доставка не имитируется. Можно сохранить карточку и отправить вручную.

## Как устроена отправка

Получатель задан только на сервере. Сервер проверяет источник запроса, размер и формат данных, пересчитывает результат из допустимых вариантов. Resend получает постоянный ключ идемпотентности, поэтому повтор запроса после сбоя не создаёт второе письмо в пределах окна идемпотентности провайдера. Встроенный лимит запросов действует на один экземпляр функции; для большого публичного трафика можно добавить правила Vercel Firewall.

Приложение не загружает сторонние картинки и шрифты во время просмотра: фотографии, иконки и шрифты включены в проект. Встроенный `noindex` просит поисковики не индексировать страницу; доступ по ссылке остаётся открытым. Файлы из `public` доступны посетителям сайта, а в открытом GitHub-репозитории — также читателям репозитория.
